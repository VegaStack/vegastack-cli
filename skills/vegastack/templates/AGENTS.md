# AGENTS.md

This project uses [@vegastack/cli](https://github.com/vegastack/vegastack-cli) — a local-first VegaStack Registry harness — to ground infrastructure, cloud, CI/CD, and Terraform questions in deterministic local docs instead of model memory.

Project config lives in `.vegastack/vegastack.yml` (committed). Registry data and managed tools live in `~/.vegastack/`. Shared agent instructions live under `~/.vegastack/instructions/` and are referenced from this file by `vegastack init`.

## How to use the CLI

- Build grounded evidence: `vegastack ask "<question>"`.
- Exact citation lookup: `vegastack search --pack <pack> "<literal>"`.
- Terraform-specific: `vegastack ask --pack terraform --tf-provider <provider> "<query>"`.
- First-run / status: bare `vegastack`.
- Project setup: `vegastack init`.
- Refresh selected packs: `vegastack registry update`.
- Security scan: `vegastack scan`.
- Health check: `vegastack doctor --verify-registry`.

Use `--agent` to receive a structured JSON envelope instead of human-formatted output.

## Hard rules for agents

- Do not invent resource names, arguments, import IDs, workflow keys, CLI flags, or provider behavior — the CLI's response is the source of truth.
- Cite every file path the CLI returned in your reply.
- Trust dated knowledge cards (`knowledge[]` with `overrides_training: true`) over training memory.
- Never print secrets from `.env`, shell history, cloud credentials, CI variables, or kubeconfigs.
- Before mutating infrastructure, deployments, CI permissions, or production data, show the planned change and ask before applying.

This file is generated by `vegastack init`/`vegastack skills install`. Hand edits between `<!-- vegastack:begin -->` and `<!-- vegastack:end -->` markers (when present) are overwritten on update.
