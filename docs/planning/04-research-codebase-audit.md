## 2. Architectural smells (will hurt at 100 providers)

**Provider-name table everywhere.** List of 31 providers in: discover.py:14-20, src/lib/discover/constants.ts:29-61, README.md:19, skills/terraform-docs/SKILL.md:3,11, AGENTS.md:9, package.json keywords. Adding the 32nd needs ~7 file edits. Move to one source of truth (bundle's root MANIFEST.json), consume everywhere.

**Score scale is per-provider.** F7. At 31 we tolerate; at 100 the feature "given an ambiguous query, show best result FROM EACH provider" is impossible because raw-score comparisons across providers are meaningless. Cross-provider recipes need this normalization.

**Hand-curated alias tables embedded in code.** SUBCAT_KEYWORDS (~80), PRIMARY_RESOURCES (~50), SERVICE_ALIASES (~40), TOKEN_EXPANSIONS (~25), PROVIDER_TOKEN_EXPANSIONS (~12) all in src/lib/discover/constants.ts (and twin Python). Each provider needs human curation across all five tables. By 100 providers this is a 1500-line file plus a Python clone. **Externalize into per-provider YAML alongside each MANIFEST.json so docs-bundle owner controls them.**

**No telemetry.** vegastack tf writes nothing to a log; failed rankings invisible. Add --debug log file with per-stage hit/miss counters and threshold-decision traces.

**subcategory_useful is binary.** Provider's subcategories either fully trusted (AWS) or fully ignored (Cloudflare, Snowflake). For mixed-quality (Vault) no middle ground. synthetic_subcategories fallback re-buckets by first-name component, producing nonsense like pki_external (2 entries) for 200-resource provider. Replace with per-subcategory-key trustworthiness scoring.

**Native TS port + Python harness double maintenance.** constants.ts:1-7 literally says "When you change a table here, also update Python source and re-run parity test" — but parity test does not exist (F13). Two implementations + zero parity test = guaranteed drift. Pick one, or auto-generate one from the other.

**Manifest schema bumps require fleet-wide rebuild.** manifest_builder.py:93 (MANIFEST_SCHEMA_VERSION = 4); sync_docs.sh has to force-republish every provider. With 100 providers, weekly events. Make additive / backward-compatible by default.

**Tier-2 grep is not a fallback, it's an acknowledgement of failure.** Plumb as parallel-confirm — kick off Tier-2 in parallel as soon as Tier-1 starts; merge when both finish. Latency stays at slower of the two.

**Cold-cache critical path: ~70-150 ms.** JSON.parse of 6 MB AWS manifest ~50 ms; python3 -c startup ~30 ms; ripgrep startup ~10 ms. Hot path drops to <10 ms thanks to manifest.ts:16 mtime cache. (a) Ship pre-parsed binary serialization (msgpack), (b) lazy-load only resource subsets the query needs (split per-subcategory at build time).

**No bundle-version pinning.** npm/install.js:80 derives bundle version from CLI's package.json version. So CLI cannot update independently of bundle. With 100 providers: "32 KB CLI patch needs to redownload 250 MB of docs." Decouple cli_version and bundle_version; pin a bundle_version range in package.json.

## 4. What's actually solid (keep)

- **npm/install.js SHA256 verification + streaming download + size caps + atomic swap + lock file.** Genuinely well-engineered.
- **npm/safe-tar.js defense-in-depth extraction.** Dual-pass listing + per-entry path-traversal validation BEFORE extract is right shape.
- **src/lib/validate.ts.** TOCTOU-aware realpath checks, control-character + bidi-override rejection — production-grade. Only problem: discover.ts doesn't call it (F20).
- **src/lib/discover/manifest.ts mtime cache.** Simple, correct; warm path sub-millisecond.
- **The native TS port's structure.** tier1 / tier2 / merge / intents / enrich / tokenize / provider separation is clean. Each stage independently testable — just nothing tests them yet (F13).
- **Two-tier (manifest + grep fallback) discovery model.** Fundamental design sound.
- **manifest_builder.py HCL reference graph + bigram typo fallback + example_token + import_syntax + deprecation flag extraction.** All useful, all working. Bug is in schema parser (F1, F2), not indexes.
- **Tier-1 DEDUPE_REASON_KINDS.** Prevents triple-stacking same reason on a file.
- **src/agents/* per-agent installer abstraction.** Symlink-or-copy fallback for Windows non-admin, dry-run mode, status idempotency.
- **Per-agent installer tests.** tests/agents/*.test.ts covers all four installers — only piece with real coverage.
- **scripts/generate-skills.ts deterministic output.** Sorted keys, no timestamps — right idea.

## 5. Test coverage gaps
- No tests for src/lib/discover/* at all. Twelve modules, zero .test.ts files. Promised parity test does not exist.
- No tests for src/commands/{doctor,install,refresh,skills,tf}.ts.
- No tests for manifest_builder.py. Bug F1 caught by single fixture test.
- No fuzz testing of safe-tar.js against malformed tarballs. F16 alignment-mismatch obvious gap.
- evals/evals.json has 4 prompts vs 12-prompt eval set. The 12-prompt set missing from repo; consequently every claim about discovery quality unverifiable.
- Cross-platform tests: zero. Windows path-separator handling in path-weight.ts (uses /r/ and /d/ substring matches — Windows \\r\\ would never hit), safe-tar.js (assumes POSIX tar), install.js (assumes HOME).
- Skills install partial-failure recovery untested.
