# 2026-05-08 — file-naming standards

Seven findings on root-level file naming. None of these are functional bugs; they affect first-impression OSS UX, GitHub auto-detection (CONTRIBUTING, CODE_OF_CONDUCT, SECURITY templates), and tooling that scans for canonical filenames.

## F18 — `GET_STARTED.md` is non-standard

- **Where:** `/GET_STARTED.md`
- **Observed:** underscore-imperative form. Rare in OSS.
- **Convention:** GitHub/community uses `GETTING_STARTED.md` at root (uppercase, gerund) **or** `docs/getting-started.md` (lowercase-kebab in a docs dir).
- **Fix:** rename to `GETTING_STARTED.md`. Update:
  - `package.json:files` (line ~57)
  - `README.md` link (`[GET_STARTED.md](GET_STARTED.md)`)
  - any CHANGELOG entries that mention it
- Optional: add a `GET_STARTED.md` redirect stub for one release, then delete.

## F19 — `STYLE.md` is non-standard

- **Where:** `/STYLE.md`
- **Convention:** `STYLEGUIDE.md` or `STYLE_GUIDE.md`. The file's first line already self-titles "STYLE.md — review-time guidance for `@vegastack/cli`" — the file *is* a style guide.
- **Fix:** rename to `STYLEGUIDE.md`. Update `CONTRIBUTING.md` link (`[STYLE.md](STYLE.md)`).

## F20 — `cursor-rule.mdc` at repo root

- **Where:** `/cursor-rule.mdc`
- **Convention:** Cursor's own docs use `.cursor/rules/<name>.mdc` (hidden directory, plural "rules", project-scoped).
- **Observed:** singular file at repo root. Unclear if it's:
  - a build-time template consumed by `src/agents/cursor.ts` (in which case it should have a top-of-file comment saying so), or
  - a stray copy that's actually unused.
- **Fix:** move to `.cursor/rules/vegastack-cli.mdc` (matching what `src/agents/cursor.ts` emits into a project), **or** add a comment at the top: `<!-- Source template for src/agents/cursor.ts; do not edit installed copies. -->`.

## F21 — `CONTEXT.md` is unusual at root

- **Where:** `/CONTEXT.md`
- **Observed:** title says "Gemini context"; content is Gemini-specific.
- **Convention:** Gemini Code Assist uses `GEMINI.md` (matching `CLAUDE.md` for Claude, `AGENTS.md` for the cross-agent spec).
- **Fix:** rename `CONTEXT.md` → `GEMINI.md`. Update:
  - `package.json:files`
  - `src/agents/gemini.ts` legacy installer if it copies `CONTEXT.md` by name
  - any references in `CONTRIBUTING.md`, `AGENTS.md`, `STYLE.md`/`STYLEGUIDE.md`
- This also resolves F23.

## F22 — Hidden artifacts in repo root (mostly fine)

- **Where:** `/`
- **Observed:** `.agents`, `.changeset`, `.claude`, `.claude-plugin`, `.editorconfig`, `.github`, `.gitignore`, `.mcp.json`, `.npmignore`, `.npmrc`, `.nvmrc`, `.prettierignore`, `.prettierrc.json`
- **Fix:** add a one-paragraph "Repo layout" appendix to `CONTRIBUTING.md` listing each. Verify `.npmrc` doesn't carry secrets (it shouldn't on a public OSS repo). `.agents` is unusual — confirm it's intended.

## F24 — `gemini-extension.json` location

- **Where:** `/gemini-extension.json`
- **Observed:** root-level JSON manifest for Gemini Code Assist.
- **Convention check needed:** verify Google's current canonical extension path. Some Gemini docs use `.gemini/extension.json` (hidden dir + lowercase). If `.gemini/extension.json` is the modern form: support both during transition. If root JSON is canonical: leave it.
- **Fix:** confirm with Gemini docs and document the choice in `references/skills.md`.

## F26 — `dist/` is committed

- **Where:** `/dist/`
- **Observed:** present in `ls`. Most TypeScript libraries don't commit `dist/` — they let `prepublishOnly` build.
- **Fix:** confirm intent. If only for local testing, add to `.gitignore` and remove the committed copy. If intentional (e.g., users install from git tag), document why.

## F27 — `.npmignore` AND `package.json:files` both present

- **Where:** `/.npmignore`, `package.json:files`
- **Observed:** when `files` allowlist is present, npm ignores `.npmignore` — but contributors don't always know that.
- **Fix:** delete `.npmignore`. The `files` allowlist is authoritative.
