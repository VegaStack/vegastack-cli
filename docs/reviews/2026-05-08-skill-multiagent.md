# 2026-05-08 — skill + multi-agent consistency

Five findings on the `vegastack` skill artifact and its 6-host coverage (claude-code, codex, cursor, gemini, continue, aider).

## F4 — `ALL_AGENTS` (4) vs `ALL_RENDERERS` (6) split is undocumented

- **Where:** `src/agents/index.ts:17-33`
- **Observed:** `ALL_AGENTS` exports 4 (claude-code, codex, cursor, gemini); `ALL_RENDERERS` exports 6 (adds continue, aider). The header comment marks `ALL_AGENTS` as legacy and used by `vegastack skills install` "today", but the skills command was already migrated (see F31).
- **Why it matters:** any downstream consumer that imports `ALL_AGENTS` silently sees an incomplete agent list. New contributors don't know which to extend.
- **Fix:** add `@deprecated` JSDoc on `ALL_AGENTS` pointing to `ALL_RENDERERS`; add a one-line Unreleased CHANGELOG entry; consider deleting `ALL_AGENTS` entirely after a one-version deprecation window.

## F5 — `skills/vegastack/agents/` only contains `openai.yaml`

- **Where:** `skills/vegastack/agents/`
- **Observed:** single file `openai.yaml`. No companion files for claude-code, cursor, gemini, codex, aider, continue.
- **Why it matters:** the directory name implies multi-agent skill artifacts live here. Reviewers and skill consumers will assume the other 6 agents are missing or broken.
- **Fix:** decide one of:
  1. **Populate** — emit per-host companion files (mirror what `vegastack skills install --host <name>` writes).
  2. **Delete** — remove the directory and `openai.yaml`. Multi-agent install is already handled by `src/agents/*.ts`; the directory is vestigial.
- Recommend (2) unless there's a downstream tool that reads `skills/vegastack/agents/`.

## F6 — SKILL.md / `references/skills.md` never enumerate the 6 supported hosts

- **Where:** `skills/vegastack/SKILL.md`, `skills/vegastack/references/skills.md`
- **Observed:** no list. `src/cli.ts:48` has the canonical list as `VALID_AGENT_HOSTS = ${ALL_RENDERER_NAMES.join(", ")}, all`.
- **Fix:** add a short "Supported agent hosts" section to `references/skills.md` derived from `ALL_RENDERER_NAMES` (ideally generated by `scripts/generate-skills.ts` to avoid drift). Add a one-line pointer in `SKILL.md`.

## F10 — Two divergent Gemini install layouts

- **Where:** `src/agents/gemini.ts`
- **Observed:**
  - **Modern renderer (line ~79):** writes `~/.gemini/extensions/vegastack/{gemini-extension.json,skills/SKILL.md,commands/vegastack.toml}`
  - **Legacy installer (lines ~208-314):** writes project-level `gemini-extension.json` + `CONTEXT.md`
- **Why it matters:** users with both code paths active see two install footprints; AGENTS.md/SKILL.md don't say which is canonical.
- **Fix:** pick one canonical layout, document it in `references/skills.md` with the legacy path noted, and ensure `src/agents/types.ts` comment matches (see F30).

## F12 — `references/skills.md` example uses `--host` without intro

- **Where:** `skills/vegastack/references/skills.md:1-5`
- **Observed:** first command shown is `vegastack skills install --host all --dry-run --agent`, but `--host` is never explained in this file before that example.
- **Fix:** one-sentence preamble: "`--host` accepts a single agent name, a comma-separated list, or `all`. Valid names: …" — derive the list from `ALL_RENDERER_NAMES`.
